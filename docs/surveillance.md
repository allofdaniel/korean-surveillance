# 항적 처리 구조 (Surveillance data processing)

ATC 감시자료처리시스템(EUROCONTROL ARTAS, Thales TopSky, Indra iTEC 계열)의 처리 단계를
브라우저 안에서 그대로 따른다. 코드는 `src/surveillance/tracker.ts`, 연결은 `src/hooks/useSurveillance.ts`.

```
/api/aircraft (2 s)            seen_pos · now
      │
      ▼
① 시각 등록   위치 유효시각 = 서버시각 − seen_pos, 클라이언트 시계로 변환(오프셋 추정)
      │
      ▼
② 연관        ICAO 24-bit 주소로 트랙에 연결. 유효시각이 이전과 같거나 더 오래된 보고는
              운동학 정보 없음 → 편명·스쿽 등만 갱신 (엣지 캐시의 중복 스냅샷)
      │
      ▼
③ 타당성 게이트  예측 위치와의 차이가 게이트(≥400 m, 5σ)를 넘으면 1회 무시, 2회 연속이면 트랙 재초기화
      │
      ▼
④ 트랙 필터   축별 2상태(위치·속도) 칼만 필터, 국소 ENU(m). ADS-B 지상속도·트랙은 속도 관측값으로
              직접 사용. 선회율(track_rate 또는 트랙 변화)로 정상선회 모델 외삽 (IMM-lite)
      │
      ▼
⑤ 트랙 상태   fresh (위치 12 s 이내) → coasting (외삽, 반투명) → dropped (공중 60 s / 지상 30 s 무보고)
      │
      ▼
⑥ 표시        표시시각 = 현재 − 0.8 s(지터 버퍼)로 외삽. 새 보고로 추정이 움직이면 화면 심볼은
              보정 벡터를 지수적으로 줄이며 따라가고, 보정 속도는 지상속도의 45 %+3 m/s로 제한
              → 공중 심볼이 뒤로 가는 일이 없다. 지도·차트 뷰어·교통 목록·카드가 같은 그림을 쓴다.
```

## 왜 바꿨나
예전에는 보고를 받은 시각을 위치 시각으로 찍었다. 45 s 묵은 위치를 "지금"으로 보고 앞으로 예측한 뒤
다음 보고가 오면 뒤로 끌려가는 일이 반복됐다. 실측(운영 사이트 40 s 샘플, 90여 트랙):
후진 프레임 1119 → 0~2, 최대 프레임 점프 8.6 km → 0.3 km(재초기화 제외).

## 튜닝 값 (`tracker.ts` 상단)
σ_pos 30 m · σ_vel 1.5 m/s · σ_acc 1.5 (공중) / 1.2 (지상) m/s² · 표시 지연 0.8 s · 최대 외삽 70 s.

## 검증
`npx vitest run src/__tests__/surveillance` — 시각 등록, 중복 스냅샷 단조성, 보정 완화, 게이트/재초기화,
coasting/drop, 정상선회 추종.
